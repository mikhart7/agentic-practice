# Claim R10 (ветка r10-refit, направление 10: финальная доводка проверенных механизмов, обучение на всех 756 записях train)

Дата: 2026-11-06. Квота: до 3 мест (r10-01, r10-02, r10-03). Родители: r8-01 (ансамбль + лексика, curve 0.800), r6-01 (ансамбль, 0.79725), r4-01 (лексика + bge-base, 0.7825).

## Гипотеза
Параметры, которые обучает build (средний запрос каждой модели для центрирования, дискретные веса ансамбля, 1-11 скаляров слияния с лексикой, выбор метода слияния), навык-независимы. Обучение на 756 записях вместо 556 (+36%, 189 семейств вместо 139) уменьшает дисперсию этих оценок и может улучшить перенос на новые запросы и навыки.

## Механизм (минимальное изменение)
Пакеты r10-01 = r8-01, r10-02 = r6-01, r10-03 = r4-01; единственное изменение логики: build читает `train.jsonl` + `train.meta.jsonl` (точные копии `case/dataset/*`, склейка по id, контрольные суммы пишутся в report.json) вместо выборки из 556 записей. CV по family остаётся. Чистая упаковка: без `__pycache__`/`*.pyc`, без неиспользуемых файлов; README описывает механизм выбора, а не устаревшие значения.

## Область
Все стили. Ожидание: небольшой выигрыш (0..+1 п.п.), если веса/слияние на 556 записях были шумными; на train_curve эффект проверить нельзя (все 200 запросов в обучении).

## Ожидаемый эффект
Public: не хуже родителя (шум ±2.5 п.п. на 380); CV в build на 756 записях сопоставима с родителем (0.83-0.84).

## Опровергающая проверка
1. Выбор в build (ансамбль, метод слияния) совпал с родителем и CV-оценки почти те же: эффект сведётся к сдвигу mu_q и перебору, ожидать разницы в пределах шума.
2. Public (оркестратор): не лучше родителя: дополнительные 200 записей не помогают.
3. train_curve при таком обучении НЕ независим (запросы и семейства curve в обучении): его score служит лишь проверкой исправности пакета и упаковки (заметно ниже родителя было бы сигналом дефекта), но не оценкой переноса.

## Происхождение train-сведений
`train.jsonl` (756 запросов, sha256 `9c2e9857...`) и `train.meta.jsonl` (sha256 `0cbb754b...`): копии `case/dataset/*`. Назначение: только обучение общего механизма в build (ADR-0004: обучение на train в build). Таблиц «запрос -> ответ» и правил под запросы нет.

Модели только в runner (build / train submit). Локально: чистый Python (склейка train, ast-проверка кода). numpy/torch/lightgbm не ставились.
