# Claim R4 (ветка r4-hybrid, направление 3 (+5): гибрид лексики и dense с обучением слияния в build)

Дата: 2026-11-05. Квота: 4 места (r4-01 ... r4-04). Родители: r1-03 (лексика 0.6415), r2-04/r2-02 (dense bge-base 0.7425/0.7395).

## Гипотеза
Лексика и dense ошибаются по-разному: dense путает близкие навыки кластера и слаб на коротких запросах, где есть точные слова-имена (там BM25 силён); лексика проваливается на indirect. Нормированное слияние (z-score взвешенная сумма, RRF, или малая логистическая регрессия на признаках лексики/dense/длины запроса) даёт выигрыш над лучшим одиночным источником. Ожидание: train_curve 0.76-0.80 (r2-04 0.7425).

## Механизм
solve считает лексические признаки (код r1-03) и dense (numpy-энкодер bge-base, как r2-04) и применяет параметры слияния из `/assets/prepared/fusion.json`. build считает эмбеддинги каталога и dense-признаки обучающих запросов (556 записей train в пакете как текст), выбирает метод слияния и параметры групповой CV по family и пишет fusion.json. Обучается общий механизм слияния (несколько весов), а не запрос->ответ.

## Область
Все стили; ожидаемый выигрыш на cmd/casual/question (лексические подсказки) и сохранение indirect на уровне dense.

## Происхождение train-сведений
Для замера на train_curve из обучающих записей исключены все 50 семейств train_curve (556 записей, 139 семейств, общих навыков с curve нет). Назначение - обучение слияния в build (ADR-0004). Описано в README кандидата.

## Опровергающая проверка
- score <= r2-04 + 0.01 на train_curve: слияние не добавляет к dense при n=200 (шум SE ~3 п.п. оговорить).
- выбор по CV в build показывает fused CV не выше dense_only в report.json: лексика не дополняет dense.
- indirect acc@1 ниже, чем у dense (0.56-0.58): лексика портит.
