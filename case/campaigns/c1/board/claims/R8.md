# Claim R8 (ветка r8-final, направление 8: объединение лучших механизмов)

Дата: 2026-11-05. Квота: 3 места (r8-01 ... r8-03). Родители: r6-01 (ансамбль энкодеров + центрирование, curve 0.79725), r4-01 (лексика + bge-base, обученное слияние, 0.7825), r7-01 (гибрид + центрирование, 0.7865).

## Гипотеза
Выигрыши r6 (разнообразие dense) и r4 (лексика) аддитивны хотя бы частично. Основание из ответов curve (чистый Python): r6-01 против r4-01 парно 18 лучше / 13 хуже; r6 выигрывает в casual (+4/-2), indirect (+6/-1), typo; r4 выигрывает в question (-4/+2), verbose (-2/+1). Потолок «оракул r6|r4» по acc@1 0.815 против 0.760 и 0.755 у каждой версии. По CV (report r6-01, `/derived/fc53d88e...`) ансамбль 0.8344 против гибрида r7-01 0.8241; по стилям CV: ансамбль лучше в indirect (0.700 против 0.635) и casual (0.880 против 0.830), гибрид лучше в question (0.843 против 0.778) и verbose (0.954 против 0.913): ошибки частично разные.

## Механизм
build (runner): dense-ансамбль как r6-01 (4 энкодера, центрирование, z-слияние; выбор весов по групповой CV); поверх него признаки лексики r1-03 (BM25 + триграммы). Варианты слияния: `ens` (без лексики), `wz` (z ансамбля + w * z лексики), `wz2`, `lr` (softmax-регрессия, признаки как r4-01 с z ансамбля), `lrm` (то же с отдельными z каждой модели). Выбор по 5-fold CV по family на 556 записях; лексика включается только если CV лучше `ens` не менее чем на 0.004 (иначе результат совпадёт с r6-01 и на curve не измеряется).

## Область
Все стили; ожидаемо question/verbose/typo поднимаются за счёт лексики, indirect остаётся как у ансамбля (лексика r1-03 на indirect acc@1 0.18).

## Ожидаемый эффект
CV +1..2 п.п. к ансамблю; curve 0.797 -> 0.81..0.82; время solve +~1 с к r6-01 (~5 с).

## Опровергающая проверка
1. CV в build: `lexical - ens < 0.004` => лексика поверх ансамбля не аддитивна; curve не измеряется.
2. curve: не лучше r6-01 (0.79725) более чем на 0.5 п.п. и парно не лучше => аддитивности нет.
3. По стилям: если indirect CV/curve не растёт против `ens`, гибрид indirect не решает (ожидаемо).

## Происхождение train-сведений
`fit.jsonl` (556 записей train вне 50 семейств train_curve, тот же файл, что у r6-01). Назначение: средние запросов (центрирование), выбор весов ансамбля и параметры слияния лексики (несколько скаляров) групповой CV, ADR-0004 (обучение на train в build). Таблиц запрос->ответ и правил под запросы нет, solve файл не читает.

## Процедурное
Модели только в runner (build / train submit). Локально: чистый Python для анализа ответов curve; numpy из ~/np_test (вне пакета) только для синтетической проверки логики на случайных векторах, не для эмбеддингов.
