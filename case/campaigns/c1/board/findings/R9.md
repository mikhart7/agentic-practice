## r9-02 (confidence-gated lexical)
Находка из анализа CV r9-01: лексика r8-01 теряет на indirect (CV ens 0.699 -> wz 0.652): в 13 запросах indirect она ломает верный ответ ансамбля, в 3 чинит; ломает там, где пик косинуса триграмм запроса по каталогу `tpk` низкий (среднее 0.20 у indirect против 0.33-0.44 у остальных; AUC «indirect по низкому tpk» 0.87; случайные подстроки: stats -> gitlab, ads -> rss). Метод `gate`: z(ансамбль) + wmax*sigmoid((tpk-c)/s)*z(лексика), 3 параметра, сетка 196 точек внутри фолдов.
Build (runner, 191 с): CV на 3 разбиениях ens 0.8337, wz 0.8368, wz2 0.8371, **gate 0.8449** (по повторам 0.846/0.844/0.845); выбран gate. По стилям (CV) gate / wz / ens: indirect 0.675/0.655/0.699, cmd 0.920/0.910/0.905, question 0.825/0.827/0.778, verbose 0.958/0.953/0.913, typo 0.903/0.909/0.890. Оффлайн на 8 других разбиениях: gate против wz +1.25 п.п. (CI по семействам [+0.4, +2.2], лучше/хуже 33/11), на всех 11 разбиениях gate лучше wz (+0.2…+1.8). Оптимистичность: форма gate выбрана по тем же 556 запросам (тип признака из 4 пробных).
Curve: **не измерена**. exp1 (3 примера) выполнен, но запись в журнал упала на отрицательном `judge_seconds` (-15.09; известная аномалия train-сервиса): ответ сервиса сохранён в `runs/r9-02-exp1.json` (2 из 3 верно, как r8-01), измерение `r9-02-exp1` в журнале осталось running. Curve `r9-02-curve` (evaluation 941152d5...) была прервана закрытием сессии (FAILED на 54 из 200, solver 516 с); повтор `r9-02-curve-b` через `measure.py` вернул тот же evaluation_id (train-сервис дедуплицирует идентичный запрос) и тоже FAILED за 7 с; измерение записано в журнал как FAILED, нового запуска не произошло. Чтобы получить curve, нужно решение оператора (новый запрос с другим идентификатором, например сброс записи). Мой единственный повтор потрачен без результата.
Ретроспективная оценка по ответам r6-01 и r8-01 на curve (чистый Python, лексика `lex.py` на 200 запросах): все 7 запросов curve с `tpk` < 0.25, на которых r6-01 (без лексики) и r8-01 расходятся в топ-1, неверны у обоих → gate на curve почти нейтрален (оценка по порогу 0.25: 0.8008 против 0.800). То есть curve не сможет подтвердить или опровергнуть gate: проверка возможна только на public/fit-подобных данных.

## Подтверждено
- LightGBM доступен в runner (build), деревья переносятся в JSON и считаются numpy в solve без lightgbm (max diff 0.0); build ~190-200 с, solve как r8-01.
- Confidence-gated лексика: CV +0.8…+1.2 п.п. над wz на fit (повторные разбиения, CI > 0), механизм (лексика вредит при низком пике триграмм) проверяется по ответам.
- r9-01 (prfsm) на curve 0.80225 — в шуме относительно r8-01 0.800.

## Опровергнуто
- (А) PRF/сглаживание/хаб-поправка по графу навыков: CV +0.0…+0.3 п.п. к wz (в шуме), на indirect не лучше; граф идентифицирует кластер, не член; MMR по графу вредит.
- (Б) GBDT-ранжировщик навык-независимых признаков: CV +0.3…+0.8 п.п. к wz, не лучше 3-параметрического gate (0.8445), выигрыш на indirect (0.69) оплачен потерей на question/typo/verbose; итог неотличим от шума.
- Нелинейное слияние не достаёт золотой вне топ-3 (20 запросов curve): сигнал для них отсутствует во всех признаках из имеющихся энкодеров и лексики.

## Ограничения
n=200 (SE ~3 п.п.), curve общий для кампании, настройка по нему не независима (в r9 curve не использовался для выбора); выбор методов по 556 запросам fit (оптимистичность ~0.5-1 п.п.). Оффлайн-анализ использует дамп оценок, посчитанный в runner. r9-02 на curve не измерена.
