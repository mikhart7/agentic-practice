## Что подтверждено
- Центрирование внутри гибрида аддитивно по CV: +0.9 п.п. (0.8147 -> 0.8241; парно 37/21), на невидимых навыках в основном indirect (+3) и question (+5), но меньше, чем +2.4 п.п. над чистым dense: часть эффекта уже забирает z-нормировка по навыкам внутри запроса и слияние. На curve +0.4 п.п. к r4-01 (в шуме, SE ~3 п.п.).
- numpy-реализация кросс-энкодера ms-marco-MiniLM-L6-v2 (токенайзер пар, token_type_ids, пулер tanh, линейная голова) совпадает с transformers: максимум |разница| логита 2.9e-6 на 4 запросах x 7 документах; это убирает +9-10 с на пример (импорт torch) — код `enc.py::CrossEncoderNP`, пригоден для любых будущих кандидатов с MiniLM.

## Что опровергнуто
- Гипотеза 2: кросс-энкодер MiniLM как признак на кандидатах гибрида не окупается ни по качеству, ни по цене: CV хуже, чем без него (raw 0.8147 -> 0.8059, cen 0.8216 -> 0.8100), на 556 запросах вне фолда чаще ухудшает (7 лучше / 15 хуже; 8/20), ни один стиль не выигрывает кроме verbose (+0.0 в шуме). Причина: ms-marco обучен на веб-запросах и не различает близкие описания этого каталога лучше слияния лексики и dense (согласуется с R3: acc@1 внутри топ-20 лишь 0.754). Поэтому кросс-энкодерная версия на curve не регистрировалась и не измерялась: CV на 556 запросов тот же вопрос, что curve (n=200), и отвечает отрицательно с большим числом запросов.
- «Центрирование + гибрид даёт заметный выигрыш на curve»: +0.4 п.п. к r4-01 в шуме.

Выбор конфигурации сделан CV на 556 запросах (не curve); curve независим для этого выбора, но train_curve уже виден нескольким исследователям, поэтому не независимая проверка для итогового набора.

## Рекомендация
- r7-01 как лучший по CV гибрид (CV 0.8241 против 0.8147 у r4-01) и по curve на уровне r4-01/r4-03 (0.7865): кандидат в финальный набор наравне с r4-01; выбор между ними по curve невозможен. Центрирование стоит ничего (нет обучаемых матриц), поэтому при равенстве предпочтителен r7-01 по CV.
