# Findings R5 (ветка r5-adapt, направление 5: обучение внутри build для улучшения dense-представления)

Claim: `board/claims/r5.md`. Git: ветка `r5-adapt`, worktree `/workspace/.claude/worktrees/agent-ae29ccf62fbc53b85`, r5-01 `c1f03c4`. Модели локально не запускались (только чистый Python для анализа ошибок по `runs/r2-04-curve.json`). Обучающие записи: `fit.jsonl` (556 записей train вне 50 семейств train_curve; ADR-0004 «обучение на train: линейный адаптер, калибровка»).

## Структура данных, влияющая на схему валидации
У каждого навыка в train ровно одно семейство (4 перефраза одного намерения). Поэтому групповая CV по family = leave-skill-out: измеряется перенос на новые навыки. Идея (г) (усреднить эмбеддинг навыка с его обучающими запросами) на этом разбиении непроверяема: для навыков curve обучающих запросов нет вообще, а «другое намерение того же навыка» (как на public/private) в train отсутствует. Не выбиралась; риск заучивания экземпляров остаётся.

## Анализ ошибок r2-04 на curve (чистый Python)
60 ошибок acc@1 из 200: 22 внутри кластера, 38 в другом; верного навыка нет в топ-3 у 28. По стилям ошибок: indirect 21/50, casual 10/30, question 10/32, cmd 7/50, typo 7/21, verbose 5/17. Типичный механизм: «ловушечное слово» (invoices -> счета вместо памяти ассистента).

## r5-03 (родитель r5-02), коммит "r5-03: partial whitening config grid" - **замер на curve не проводился**
- Гипотеза: частичное отбеливание (ZCA со степенью/сглаживанием по ковариации запросов train и навыков) добавляет к центрированию.
- Проверка только через build (`r5-03-exp1`, 1 пример, build 136.6 с, `report.json` публикации `d68be08f…`). CV: (степень, eps) = (0.25, 0.1) 0.7833; (0.5, 0.1) 0.6688; (0.5, 1.0) 0.7489; (1.0, 1.0) 0.6438; (0.5, 0.01) 0.5591; центрирование 0.8004; база 0.7764. **Опровергнуто:** отбеливание любой силы хуже центрирования (и (0.25, 0.1) ниже базы); чем сильнее выравнивание, тем хуже (шумовые направления усиливаются при 556 запросах + 189 навыках в 768 измерениях).
- Build выбрал ровно конфигурацию r5-02 (центрирование, `config_final` без whiten) => `emb.npy`/`adapter.npz` совпадают с r5-02 по существу; сопоставимый замер на curve дал бы повтор r5-02, поэтому **не запускался** (протокол: корректный ответ не повторяется ради балла). Место из квоты потрачено (3 из 4).
- Замечание для оркестратора: `measure.py` на `r5-03-exp1` упал при `evaluator.train result`: `SearchError: seconds must be finite and nonnegative` - в ответе train-сервиса `judge_seconds = -15.85` (отрицательное время судьи; рассинхрон часов). Измерение `r5-03-exp1` остаётся `running` в журнале (статус `running: ["r5-03-exp1"]`). Инструмент не правил. Данные примера сохранены в `runs/r5-03-exp1.json`.

## Подтверждено
- Обучение в build на 556 записях с групповой CV по навыкам переносится: CV +2.4..+2.8 п.п., curve +3.0..+4.0 п.п. над r2-04 (train_curve не участвовал ни в обучении, ни в подборе).
- Основной механизм - центрирование (общее смещение пространства), не контрастивное обучение; адаптер добавляет в пределах шума.

## Опровергнуто
- (в) Дообучение энкодера в 600 с: проба в runner - полный шаг 12.3 с на 32 запроса (top-4 слоя 6.7 с, прямой проход 5.2 с) => эпоха 556 запросов ~3.7 мин без CV; не укладывается.
- Отбеливание сильнее центрирования: CV хуже при любых степенях (0.56-0.78).
- Режим `query` (адаптер только на стороне запроса) и ridge не лучше `shared`/центрирования по CV (при λ=0.01 переобучение: 0.743-0.77).
- Идея (г) не выбиралась: на данной структуре train (одно семейство на навык) честно не проверяется.

## Ограничения
- n=200 (SE ~3 п.п.): r5-01 vs r5-02 различимы только как «в пределах шума» (13/19 по парам). Оба результата получены на train_curve после выбора схемы по CV на других запросах, но выбор 3 версий и сравнение на одном curve делает его не независимой проверкой для итогового выбора между ними.
- Перенос на public не проверен. Для public/private навыки те же, семейства другие: групповая CV по семействам это имитирует. Для итогового кандидата fit.jsonl можно расширить до 756 записей (curve перестанет быть независимым).
- Время build r5-01 (411 с) близко к 600 с на медленном runner; r5-02 - 191 с.

## Рекомендация
- Для финалистов брать центрирование как дешёвый механизм (r5-02: нет обучаемой матрицы, меньше риска заучивания) или r5-01 (+1 п.п. на curve, в шуме, но больше обучаемых параметров и build 411 с). Центрирование (вычитание среднего запросов и навыков перед косинусом) независимо от адаптера может быть применено в гибриде R4 как предобработка dense-признака.
- Дальше: дообучение эмбеддингов в 600 с не окупается; следующее осмысленное - гибрид R4 поверх центрированного dense.
