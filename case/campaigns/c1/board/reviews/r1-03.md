### Проверка по пунктам
1. **Сопоставимость.** Единственный замер `r1-03-curve` (журнал: split `train`, subset `37f62d06…` = `train_curve`, conditions `ar04a-metric-v1-runner-d4e3f8799ccc`, состояние `succeeded`, score 0.6415) — те же subset и условия, что у остальных кривых. Разведочных замеров в журнале нет (локальные оценки на множестве A делались чистым Python вне журнала и в кривую не смешаны).
2. **Один ответ на пример.** 200 примеров, 200 уникальных id, множество id = `train_curve`; все ответы — корректные JSON-массивы <= 3 уникальных id из каталога; `attempts=0`, все вызовы `OK`. Оценки каждого примера пересчитаны независимо кодом замороженной метрики (`campaigns/c1/metric/score.py`): расхождений 0, среднее 0.6415 = score журнала = `runs/r1-03-curve.json`. input/reference в записях совпадают с `train_curve.jsonl`.
3. **Механизм.** Лексика: стоп-слова + стеммер Портера + BM25 (k1=1.2) + исправление опечаток по словарю каталога + косинус tf-idf символьных триграмм (вес 0.6). Вклад r1-03 над r1-02 — триграммы: +0.0195 на curve (0.622 -> 0.6415; question 0.636 -> 0.698, casual +0.024, indirect +0.02); локально на A +0.008. Прирост ступени r1-03 небольшой и в пределах шума (SE около 3 п.п.); парных данных по r1-02 в этом ревью не пересчитывалось. Альтернативное объяснение — шум выбора на n=200. Главный эффект всей ветки (r1-01, +0.123 к baseline BM25 0.488) — стоп-слова и стемминг; он большой и надёжный для лексики.
4. **Зашитые ответы / источники.**
   - **Словарь исправления опечаток.** Строится в `Catalog.__init__` из `name + description` каталога во время работы (`self.freq`, `self.vocab`: слова длиной >= 4, не стоп-слова); внешнего словаря и пар «опечатка -> слово» нет. Исправление — одна правка Дамерау-Левенштейна, слова от 6 букв, с первой буквой совпадающей в первую очередь, вес 0.7. Формулировок или опечаток из train в коде нет (источник — каталог, разрешён). Параметры (длина 6, вес 0.7) выбраны по train (множество A) — общие числа, см. ниже.
   - **Список стоп-слов** (`STOP`, 80 слов): служебные английские слова (a, the, is, how, ...), плюс «запросные» слова (pls, please, plz, need, want, like, get, let, help, also, any, all, about, out, over, using, use, via). Источник по claim/findings — разбор ошибок baseline на train вне curve (множество A: cmd/verbose/question/casual теряют из-за служебных слов). Проверка на утечку (чистый Python): слова не привязаны к навыкам, темам или ответам; `help`, `also`, `plz` в train-запросах встречаются 0 раз (список не скопирован из train, а составлен как общий набор), `pls` 10, `need` 21, `want` 14, `get` 21. Доменных терминов и имён навыков в списке нет: с названиями каталога (`name`) пересекаются лишь служебные слова (to, from, by, for, of, on, with, your; у 11 навыков). Это общая нормализация (удаление нерелевантных слов), а не подстановка ответа по характерным словам; пункт ADR-0004: «код решателя... токенизация, нормализация запроса» и «обучение на train». Вывод: допустимое обучение/наблюдение общего стиля запросов с небольшим риском переобучения на стиль генератора запросов (pls/plz — маркеры стиля `casual`), не lookup.
   - Каталог в пакете не копируется; `solve` читает `<assets_dir>/catalog.jsonl` (`/assets/catalog.jsonl`). Каталог не менялся: sha256 рабочего файла `412b5a50aa99…` = значению в `campaign.md`; в `git status` изменений в `case/assets` нет.
   - Записей и идентификаторов train, id навыков и правил под конкретные запросы в коде нет (проверено поиском id каталога и id train по всем файлам: единственное «попадание» `words` — имя функции). Сети, моделей, LLM нет; только стандартная библиотека.

Это неполно: по `claims/r1.md` и `findings/r1.md` по множеству A выбраны ещё k1 = 1.2, порог длины 6, веса 0.7/0.6, а список стоп-слов составлялся по разбору ошибок на A.
