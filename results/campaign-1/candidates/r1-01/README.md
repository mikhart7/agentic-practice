# r1-01: нормализация текста для BM25 (стоп-слова + стеммер Портера, k1 = 1.2)

**Гипотеза.** Ошибки baseline на non-indirect стилях в основном из-за двух причин: служебные слова запроса («the», «for», «my», «can you») набирают вес в коротких описаниях и перебивают содержательные; словоформы не совпадают («formulas»/«formula», «subscribers»/«subscribe»). Исправление токенизации и нормализации должно поднять verbose/question/casual/cmd, не затрагивая indirect.

**Механизм.** Те же поля (name + description), та же формула BM25, но: (1) стоп-слова (список в `solve.py`) убираются из запроса и из документов (если после удаления ничего не осталось, токены остаются); (2) стеммер Портера, собственная реализация на стандартной библиотеке; (3) k1 = 1.2 (подбор по train вне семейств train_curve; b = 0.75, веса полей, степень idf — плато).

**Происхождение train-сведений.** Train использован только для выбора k1 и проверки списка стоп-слов (общие параметры механизма). Таблиц запрос → ответ, словарей и слов из train в пакете нет. Каталог — единственный источник знаний решателя. build.py нет.

**Опровергающее наблюдение.** Если verbose/question не растут на семействах вне train_curve, объяснение неверно.
