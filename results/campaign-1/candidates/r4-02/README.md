# r4-02: гибрид лексики (r1-03) с ансамблем dense (bge-base + e5-small-v2 + all-MiniLM-L6-v2), слияние обучено в build

Родитель: r4-01 (лексика r1-03 + dense bge-base, обученное слияние: train_curve 0.7825; build report r4-01: CV по семействам на 556 запросах — только dense bge 0.776, лексика 0.688, слияние 0.815).

## Гипотеза
Слабое место r4-01 — стиль indirect (acc@1 0.54 против 0.58 у чистого dense r2-04: слияние с лексикой там не помогает). Рычаг — более сильный и разнообразный dense-сигнал: две малые модели из разрешённого списка, обученные на других данных (e5-small-v2, all-MiniLM-L6-v2), добавляются как отдельные признаки; обученное слияние само решает, сколько им верить. Ожидание: +1-2 п.п. относительно r4-01 по CV в build и на train_curve, в первую очередь indirect/question. Опровержение: CV в build (поле `fusion.cv`, `ens_only` против `dense_only`) не выше r4-01 (0.815) более чем на 0.5 п.п. и train_curve не выше 0.7825.

## Механизм
Как r4-01, плюс: build считает эмбеддинги каталога тремя моделями (`emb_bge.npy`, `emb_e5.npy`, `emb_mini.npy`; префиксы e5 "query: "/"passage: ", MiniLM без префикса; bge — два вида запроса, как r2-04); numpy-энкодер (`enc.py`) сверяется с sentence-transformers по каждой модели, при расхождении solve берёт sentence-transformers. Признаки (`fuse.py`): z-оценки каждого dense, ансамбль dense (bge 1, e5 0.5, MiniLM 0.5; веса фиксированы заранее, до обучения), BM25/триграммы, отставания от максимума, длина запроса. Методы слияния `wz`, `wz2`, `rrf`, `lr` выбираются групповой CV по family (5 долей, вложенно), параметры выбранного обучаются на всех обучающих записях.

## Происхождение train-сведений (ADR-0004)
Как r4-01: `train_fit.jsonl` (556 записей, sha256 `2a6d1d82...c3d4b5`) — копия записей `case/dataset/train.jsonl` и метаданных `train.meta.jsonl`, из которых исключены все 50 семейств `train_curve` (общих навыков с curve нет). Назначение — только обучение общего механизма слияния в build.py (пункт ADR-0004 «обучение на train в build»); solve файл не читает. В `/assets/prepared` только то, что считает build: эмбеддинги каталога тремя моделями, `ids.json`, `config.json`, `fusion.json` (метод и числа), `report.json`. Таблиц запрос->ответ и правил под запросы нет. Ни эмбеддинги, ни веса не считались вне build.
