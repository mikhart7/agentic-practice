# r2-02: bge-base-en-v1.5 + query-инструкция BGE; быстрый solve и быстрый build

Родитель: r2-01 (0.7345 на train_curve, ~3.9 с solve на пример).

## Гипотеза
1. Качество. Ошибки r2-01 сосредоточены в коротких запросах (`cmd`, `casual`, `question`) и `indirect`: у BGE v1.5 запрос короче документа, модель обучена с инструкцией `Represent this sentence for searching relevant passages: ` перед запросом. Ожидание: прирост acc@1 на коротких запросах (+1-3 п.п. общий).
2. Скорость (код, на качество не влияет). r2-01 тратил ~2.8 с сверх накладных контейнера (~1.1 с у лексики). Подозрение: память под веса читается постранично через memmap и импортируется scipy (erf). В r2-02: веса читаются последовательно (без pooler), erf — полином Абрамовица-Стегана (без scipy), документы в build кодирует sentence-transformers (19 с вместо 120 с на numpy), numpy-энкодер сверяется с ним на пробных запросах/выборке документов; `report.json` содержит время загрузки весов и кодирования одного запроса.

## Механизм
Как r2-01: `build.py` пишет `emb.npy`, `ids.json`, `config.json`, `report.json` в `/output`; `solve.py` читает только `/assets/prepared` и модель `/assets/models/bge-base-en-v1.5`, кодирует запрос (numpy-BERT, резерв — sentence-transformers), топ-3 по косинусу.

## Изменения относительно r2-01
`params.json: query_prefix` = инструкция BGE; новый `enc.py` (чтение весов, erf); `build.py` (эталонные векторы документов из sentence-transformers, проверка numpy-энкодера, тайминги).

## Происхождение train-сведений
Нет: train не используется.
