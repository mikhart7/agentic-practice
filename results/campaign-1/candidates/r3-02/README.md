# r3-02: лексика r1-03 -> топ-20 -> кросс-энкодер ms-marco-MiniLM-L6-v2

**Родитель:** r3-01 (то же, но bge-reranker-base), первая стадия r1-03.

**Гипотеза.** Размер кросс-энкодера не главное: лёгкая ms-marco-MiniLM-L6-v2 (22M параметров, англ. веб-запросы) даёт сопоставимое качество переранжирования топ-20 лексики за меньшее время (r3-01: ~18 с на пример, в основном загрузка 1.1 ГБ весов XLM-R). Либо, наоборот, bge-reranker-base заметно лучше разрешает близкие навыки.

**Механизм.** Идентичен r3-01; отличие - одна константа `MODEL = "ms-marco-MiniLM-L6-v2"` в `solve.py`. Пары (запрос, "name. description"), топ-20 первой стадии, полная замена порядка по логитам, ничья - по рангу первой стадии.

**Изменения относительно r3-01.** Только модель.

**Происхождение train-сведений.** Нет: train не используется.

**Опровергающее наблюдение.** Разница score с r3-01 на train_curve меньше 2 п.п. в пользу r3-01 означает, что размер модели не рычаг; MiniLM хуже лексики r1-03 (0.6415) - ms-marco-кросс-энкодер без смешивания с первой стадией вреден.
