# r10-02: r6-01 (ансамбль энкодеров с центрированием, без лексики), build обучается на всех 756 записях train

Родитель: r6-01 (train_curve 0.79725 при обучении на 556 записях без семейств curve). Ветка `r10-refit`, claim `board/claims/R10.md`, findings `board/findings/r10.md`.

## Гипотеза
Обучаемое здесь навык-независимо: средний вектор запросов каждой модели (центрирование) и выбор режима/весов слияния. Больше данных (756 вместо 556, +36%) и все 189 навыков/семейств (вместо 139) делают среднее запросов и выбор слияния устойчивее и могут улучшить перенос. Опровергает: score public не выше r6-01.

## Что изменено относительно r6-01
Только данные обучения и гигиена. `build.py` читает `train.jsonl` + `train.meta.jsonl` (копии `case/dataset/*` без изменений; склейка по id — `trainset.py`) вместо `fit.jsonl` (556 записей). Слияние (`fusion.py`), `solve.py`, `enc.py` не менялись. `fit.jsonl` удалён. В пакете нет `__pycache__`/`*.pyc`, двоичных и числовых файлов.

## Механизм (как у r6-01)
- `build.py` (runner): для каждой модели из `params.json` (порядок: bge-base, e5-small-v2, all-MiniLM-L6-v2, bge-small) кодирует каталог и все 756 запросов через sentence-transformers; проверяет numpy-энкодер (`enc.py`, он используется в solve) против эталона (косинус > 0.999). Префиксы: bge - запрос без префикса + с инструкцией BGE, e5 - `query: ` / `passage: `, MiniLM - без префиксов; пулинг по конфигам моделей, нормализация L2.
- Центрирование каждой модели: из эмбеддинга запроса вычитается среднее эмбеддингов запросов train, из эмбеддинга навыка - среднее по каталогу, затем L2.
- Слияние (`fusion.py`, единая реализация для build и solve): `z` - стандартизация оценок модели внутри запроса, взвешенная сумма; `rrf` - сумма w/(k+ранг). Перебор: z с весами {0,1,2}^4 (>= 2 моделей), RRF k=10/60 с весами {0,1}^4. Выбор: 5-fold CV по семействам (оценки каждого запроса получены со средним запросов обучающей части фолда), метрика кейса; при разнице <= 0.002 от лучшего - конфигурация с меньшим числом моделей.
- **Итоговую конфигурацию (модели, режим, веса) выбирает сам build по этим данным**; она записана в `/assets/prepared/config.json` и в `report.json` (`config_final`, `cv_chosen`, `cv_best_raw`, `fusion_table_top`). Здесь значения не фиксируются, чтобы не устареть; для справки r6-01 на 556 записях выбрал z с весами 2/1/1 (bge-base, e5-small, MiniLM). Финальное среднее запросов (`mu_q.npz`) считается по всем 756 записям (безметочная статистика).
- Зависящие от времени ветки build: `MODEL_BUDGET_S = 330` с — новая модель не начинается после этого момента от старта build (пропуск отмечается в `report.json` как `skipped: time budget`; у r6-01 4-я модель стартовала на ~140 с); таймаут build 600 с. Если рабочих моделей меньше двух, build пишет `fallback_single` и использует одну модель.
- `solve.py`: загружает только выбранные модели (вес > 0), кодирует запрос, центрирует, косинус с `emb_<модель>.npy`, слияние, топ-3. Каталог и train не читает.

## Происхождение train-сведений (ADR-0004: «обучение на train в build»: калибровка)
- `train.jsonl` (756 запросов, sha256 `9c2e9857f611e37398d7e4dcb3d7066753850798f9356fa3148acb702b6e767a`) и `train.meta.jsonl` (sha256 `0cbb754b13d668af63e8350465e1f7fd55c9a870ba3da3610b14fe571b3e970c`) — точные копии `case/dataset/train.jsonl` и `train.meta.jsonl`. Контрольные суммы пишутся в `report.json` (`train_sha256`).
- Назначение: **только обучение общего механизма в build** (средний вектор запросов каждой модели - 768/384 числа; выбор режима и весов слияния групповой CV). Таблиц «запрос -> ответ» и правил под запросы нет; solve записи train не читает.
- **`train_curve` при таком обучении не является независимой проверкой**: все 200 его запросов и 50 семейств входят в обучающие 756 записей (в r6-01 они исключались). Score на `train_curve` этой версии не оценивает перенос на новые навыки; эффект уточнения проверяется только на public оркестратором.

## Риски
Выбор слияния из ~80 конфигураций по одним данным: оптимистичная CV (шум ~1.7 п.п.), смягчено правилом простоты и дискретными весами. Время solve: несколько моделей на пример (загрузка весов ~0.9 ГБ в сумме), как у r6-01.
