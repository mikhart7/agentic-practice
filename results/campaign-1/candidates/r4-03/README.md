# r4-03: r4-01 + линейный адаптер запросов dense, обученный в build

Родитель: r4-01 (лексика r1-03 + dense bge-base, обученное слияние; train_curve 0.7825). r4-02 (три dense) не дал выигрыша на train_curve (0.7747, acc@1 ниже) и медленнее, поэтому не родитель.

## Гипотеза
В r4-01 основные потери — стиль indirect (23 из 49 ошибок acc@1; в 18 золотого навыка нет даже в топ-3): запрос описывает цель иначе, чем описание навыка, и dense-эмбеддинг запроса лежит не в той области пространства. Сдвиг эмбеддинга запроса к эмбеддингу релевантного навыка — общий для всех навыков линейный адаптер q' = norm(q + alpha * q @ Delta), ridge — может уменьшить этот стилевой разрыв. Проверка обобщения: групповая CV по family (семейство = навык), то есть оценка на навыках, которых адаптер не видел. Ожидание: +1-3 п.п. dense-only CV в build; если выигрыш < 0.5 п.п., build сам выбирает alpha = 0 и кандидат совпадает с r4-01. Опровержение: в report.json `adapter.chosen = null` или train_curve не выше 0.7825.

## Механизм
- build: как r4-01 (эмбеддинги каталога, dense/лексические признаки обучающих запросов, слияние `wz`/`wz2`/`rrf`/`lr` выбирается групповой CV). Добавлено (`adapter.py`, numpy): ridge-регрессия `Delta` (768x768, отдельно для двух видов запроса bge: без префикса и с инструкцией), мишень — нормированное среднее эмбеддингов релевантных навыков; (lambda, alpha) из сетки выбираются групповой CV по качеству dense-ранжирования; обучающие признаки слияния считаются на кросс-подогнанных (out-of-fold) эмбеддингах запросов, чтобы слияние не обучалось на утечке; итоговые `Delta` (`adapt_0.npy`, `adapt_1.npy`) подгоняются по всем обучающим записям.
- solve: как r4-01, плюс применение `adapt_*.npy` к эмбеддингам запроса, если в `config.json` задан `adapt`.

## Происхождение train-сведений (ADR-0004)
`train_fit.jsonl` (556 записей, sha256 `2a6d1d82...c3d4b5`) — копия записей `case/dataset/train.jsonl` и `train.meta.jsonl`, из которых исключены все 50 семейств `train_curve` (общих навыков с curve нет). Назначение — обучение общих параметров в build.py (веса слияния и линейный адаптер запросов; пункт ADR-0004 «обучение на train в build»). solve файл не читает; `Delta` — обученные в build веса (D x D), а не таблица запрос->навык, правил под запросы нет. Оговорка: адаптер обучается на запросах и навыках train, поэтому на навыках, присутствовавших в обучении, он может смещать запросы к ним (для train_curve этого нет: его навыки исключены; для public эффект возможен и должен оцениваться отдельно). Ни эмбеддинги, ни веса не считались вне build.
