# r2-05: bge-base-en-v1.5, ансамбль запросов + второй вид документа (имя и слова из id)

Родитель: r2-04 (0.7425 на train_curve).

## Гипотеза
Остаточные ошибки dense-семейства (r2-01...r2-04) сосредоточены в коротких запросах `cmd`/`casual`, где подсказка — имя сервиса или слово из id ("slack thread", "gcs", "linear", "backlink"): в основном виде документа `"{name}. {description}"` имя тонет в описании. Второй короткий вид `"{name} ({id_words})"` (например `Meet.bot MCP (meet bot)`) даёт этим запросам прямое сходство с названием; итоговый score = 0.75 * сходство с основным видом + 0.25 * сходство с коротким. Ожидание: +1-3 п.п. на cmd/casual/typo без потери на indirect; общий +1 п.п. Опровержение: общий score не выше 0.7425, либо indirect падает более чем на 3 п.п.
Вес 0.25 выбран заранее, не подбирался по train_curve.

## Механизм
`build.py` кодирует каталог по двум шаблонам (`doc_templates`), пишет `emb.npy` формы (2, N, D); `solve.py` кодирует два варианта запроса (без префикса и с инструкцией BGE, как в r2-04), считает косинусы к обоим видам, взвешивает (`view_weights`), топ-3. Только поля catalog.jsonl: id, name, description (описания не меняются; id уже в каталоге).

## Происхождение train-сведений
Нет: train не используется. Гипотеза основана на разборе ошибок r2-01...r2-04 на train_curve.
