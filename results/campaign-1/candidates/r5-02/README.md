# r5-02: r5-01 + центрирование перед адаптером, сокращённый перебор (build быстрее), правило «простая конфигурация в пределах шума CV»

Родитель: r5-01 (0.78275 на train_curve; CV в build: база 0.776, центрирование без обучения 0.800, shared-адаптер 0.804; сочетание центрирование+адаптер в r5-01 не успело проверяться: перебор был обрезан по времени, build 410 с из 600).

## Что нового относительно r5-01
- Перебор сокращён до конфигураций, которые по CV r5-01 имеют смысл: база, центрирование, ridge+центрирование (λ 30, 100), shared-адаптер с центрированием (λ 0.03/0.1/0.3; шаги 40/80/160). Убраны режим `query` (CV хуже shared) и замер времени шага дообучения (уже получен в report r5-01: полный шаг на 32 запросах 12.3 с, top-4 6.7 с, прямой проход 5.2 с => дообучение энкодера при 556 запросах x несколько эпох + CV не укладывается в 600 с на 2 CPU).
- Выбор: самая простая конфигурация (база < центрирование < ridge < адаптер), чей CV в пределах 0.003 от лучшего (шум CV ~1.7 п.п.); включается только при выигрыше над базой >= 0.005.


## Гипотеза
Ошибки r2-04 (60 из 200 acc@1 на curve): 38 из 60 в другом кластере, 28 из 60 без верного навыка в топ-3; в основном «ловушечное слово» в запросе (invoices -> счета вместо памяти ассистента, photos -> генератор изображений вместо поиска картинок). Общее (не зависящее от навыка) отображение запроса в пространство описаний этого каталога, обученное контрастивно на парах запрос -> навык, должно сместить ранжирование; выигрыш измеряется переносом на других навыках (CV по семействам, у каждого навыка в train одно семейство из 4 перефраз).

## Механизм
- `build.py`: bge-base кодирует каталог и 556 обучающих запросов (два варианта запроса, как r2-04, сумма и нормировка == среднее косинусов). Перебирает конфигурации (центрирование средним запросов и средним навыков; режим: нет / ridge в замкнутой форме / `query` - матрица A на стороне запроса / `shared` - одна A на обе стороны; λ; число шагов Adam для CE) 5-fold групповой CV по `family`, метрика кейса, ранжирование по всем 189 навыкам. Softmax обучения идёт только по навыкам обучающей части (навыки отложенных семейств в нём не участвуют, иначе адаптер учился бы «отталкивать» их). Выбирается лучшая конфигурация; если она лучше базы (r2-04 без изменений) менее чем на 0.005 по CV, адаптер выключается (результат совпадает с r2-04). Финальная подгонка - на всех 556 записях. `report.json`: таблица всех конфигураций (CV score, acc@1, по фолдам), выбор, CV по стилям, норма A, балл на обучающих запросах (для контроля переобучения, не качество), время фаз, плюс замер времени шага дообучения энкодера (32 запроса: полный шаг и шаг top-4 слоя) в runner - разведка для дообучения энкодера, на качество этой версии не влияет.
- `solve.py`: numpy-энкодер (как r2-02/r2-04), `x = norm(q_plain + q_instr)`, центрирование и `x = norm(x + x A)` по `adapter.npz`, косинус с `emb.npy`, топ-3. Каталог и `fit.jsonl` не читает.

## Изменения относительно r2-04
`build.py` (обучение, CV, report), `solve.py` (адаптер), `fit.jsonl`, `adapter.npz` в публикации build.

## Происхождение train-сведений (ADR-0004: «обучение на train: линейный адаптер запроса, калибровка»)
- `fit.jsonl`: 556 записей из `case/dataset/train.jsonl` (поля: id, input, primary/relevant из `reference`, family и style из `train.meta.jsonl`). Получен фильтром: исключены все записи семейств, входящих в `case/dataset/train_curve.jsonl` (50 семейств, 200 записей), поэтому замер на train_curve сопоставим и не использует ни запросы, ни навыки curve (у каждого навыка в train одно семейство).
- Назначение: обучение общей матрицы A (768x768) и среднего вектора запросов, выбор λ/числа шагов/режима по CV. Это не таблица «запрос -> ответ» и не правила под запросы: в `solve.py` нет обращения к записям train; в `adapter.npz` только обученные параметры и среднее.
- Для итогового кандидата (public/private) можно добавить 200 записей curve в `fit.jsonl` (тогда train_curve перестанет быть независимым замером).
- Риск: линейное отображение с 590k параметрами на 556 примерах переобучается; защита - L2 к тождеству, ранняя остановка по CV, групповая CV по навыкам. Идея «усреднить эмбеддинг навыка с эмбеддингами его обучающих запросов» (заучивание экземпляров) не используется.
