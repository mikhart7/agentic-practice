# r8-02: ансамбль энкодеров с центрированием (r6-01) + лексика r1-03 с затворами (лексика не действует там, где она ненадёжна); метод слияния выбирает build по групповой CV

Родители: r8-01 (то же без затворов: CV в build ens 0.8337, wz 0.8383; лексика прибавила question +6 п.п., verbose +4, typo +2 и убавила indirect -5 п.п.), r6-01 (ансамбль bge-base, e5-small-v2, all-MiniLM-L6-v2, bge-small + центрирование, train_curve 0.79725), r4-01 (лексика + bge-base, обученное слияние, 0.7825), r7-01 (гибрид + центрирование, 0.7865). Claim: `board/claims/R8.md`.

## Гипотеза
Выигрыши ансамбля энкодеров (+2.5 п.п. к одному bge-base с центрированием; typo, verbose, casual, частично indirect) и лексики (+4 п.п. к одному dense; typo, verbose, question) пересекаются лишь частично: по ответам curve r6-01 против r4-01 парно 18 лучше / 13 хуже, оракул «r6 или r4» по acc@1 0.815 против 0.760 и 0.755. Лексика поверх ансамбля должна добавить на question/verbose/cmd, ансамбль сохраняет преимущество на indirect/casual.

## Что изменено относительно r8-01
Диагноз по CV r8-01 и ответам curve r4-01/r6-01: когда в описании золотого навыка есть слово запроса, гибрид с лексикой точнее ансамбля (curve acc@1 0.88 против 0.83 при n=160), когда общего слова нет (40 из 200, 25 из 50 в indirect), лексика только путает («ловушечные» совпадения: acc@1 0.25 против 0.475). Поэтому лексика умножается на затворы: жёсткий (`rens <= K`: влияет только на навыки из топ-K ансамбля) и/или мягкий (`g = sigmoid(max z(лексика) - p0)`: уверенность запроса в лексике). Добавлены методы `wzk`, `wzc`, `wzkc`, `lrg`; остальное, включая правило выбора, как в r8-01 (лексика включается при выигрыше >= 0.004 к `ens`, самый простой метод в пределах 0.003 от лучшего, порядок wz, wz2, wzk, wzc, wzkc, lr, lrm, lrg).

## Механизм
- `build.py` (runner): кодирует каталог и 556 запросов `fit.jsonl` четырьмя энкодерами (sentence-transformers), проверяет numpy-энкодер (`enc.py`, он используется в solve) против эталона (косинус > 0.999). Центрирование каждой модели: вычитание среднего запросов train и среднего каталога, L2; z-оценка по навыкам внутри запроса. Ансамбль: взвешенная сумма z-оценок, веса {0,1,2}, выбор по метрике кейса на 556 записях (простота при разнице <= 0.002), как r6-01.
- Лексика r1-03 (`lex.py`: BM25 со стеммером, исправлением опечаток по словарю каталога и косинус триграмм) как признак поверх ансамбля. Методы (`hyb.py`, единая реализация для build и solve): `ens` (без лексики, = r6-01), `wz` (z ансамбля + w*z лексики), `wz2` (отдельно BM25 и триграммы), `lr` (softmax-регрессия по кандидатам, признаки r4-01 с z ансамбля, лексика x длина запроса), `lrm` (то же с отдельными z каждой модели). Групповая 5-fold CV по семействам (одно семейство = один навык, отложенное семейство = ещё не виденный навык). Правило выбора задано заранее: лексика включается, только если лучший метод с ней лучше `ens` не менее чем на 0.004; среди методов с лексикой берётся самый простой в пределах 0.003 от лучшего. Иначе итог совпадает с r6-01.
- `report.json` build: CV по методам и стилям, парные сравнения с `ens`, число запросов без общих слов с каталогом (BM25 = 0) и точность на них, выбранные веса. Итоговая выбранная конфигурация записана в `fusion_final`/`choice` отчёта и в `/assets/prepared/fusion.json`.
- `solve.py`: кодирует запрос выбранными моделями (numpy), центрирует, косинусы, z; при методе с лексикой читает `catalog.jsonl` и считает признаки теми же функциями `hyb.py`; топ-3. `fit.jsonl` не читает.

## Происхождение train-сведений (ADR-0004: обучение на train в build)
- `fit.jsonl`: 556 записей `case/dataset/train.jsonl` (id, input, primary/relevant, family, style) без всех 50 семейств `case/dataset/train_curve.jsonl` (тот же файл, что у r5-02/r6-01). Замер на train_curve поэтому идёт на невиденных навыках и запросах.
- Назначение: только обучение общего механизма в build: средние запросов каждой модели (центрирование), дискретные веса ансамбля, параметры слияния с лексикой (1-11 скаляров). Таблиц «запрос -> ответ» и правил под запросы нет; solve записи train не читает.
- Для итогового кандидата fit.jsonl можно расширить записями curve (тогда curve перестанет быть независимым замером).

## Риски
Выбор из ~50 конфигураций ансамбля и 4 методов слияния по одним 556 запросам: оптимистичная CV (шум ~1.7 п.п.); смягчено дискретными весами и правилом простоты. Время solve = r6-01 (~5 с, три модели) + лексика (~0.1-1 с).
