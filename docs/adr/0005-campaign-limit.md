# ADR-0005: Лимит 60 решений, K = 5 финалистов, N = 2 итоговых

- Статус: proposed (фиксируется в `campaign.md` до поиска)
- Дата: 2026-11-02

## Контекст
Единственный лимит поиска в арене — число предложенных решений, включая неудачные. Его выбирают из стоимости одного кандидата, ожидаемой сходимости и доступных ресурсов (B-4.5).

Что известно из протокола арены (`a28eee3`):
- public не обязателен для каждого кандидата. Оркестратор сам решает, кого туда отправлять, и каждый кандидат проверяется на public не более одного раза;
- кривая эволюции и AUC строятся по **сопоставимым** замерам — одинаковые split, набор и условия;
- финалисты (ровно K) проходят ревью, private оценивает их один раз и выбирает N лучших.

Стоимость одного замера (ADR-0004, [results/models/bench.md](../../results/models/bench.md)). Каждый пример — новый контейнер (2 CPU, 2 ГБ), примеры идут последовательно:

Замерено в собранном `ar04a-runner:local` (2 CPU, 2 ГБ, `network=none`, read-only, медиана из 5 запусков; [results/models/bench.md](../../results/models/bench.md)):

| что | на пример | 200 запросов (кривая) | 380 запросов (public) |
|---|---|---|---|
| пустой контейнер (`python -c pass`) | 0.4 с | — | — |
| BM25 baseline через runner | 0.7 с | 2.3 мин | 4.4 мин |
| `torch` + `transformers` напрямую, эмбеддинги каталога в пакете | ~4.2 с | ~14 мин | ~27 мин |
| то же через `sentence_transformers` | ~8.3 с | ~28 мин | ~53 мин |
| dense MiniLM, каталог кодируется на каждый запрос | 9.3 с | 31 мин | 59 мин |
| + переранжирование топ-20 bge-reranker-base | +~5 с (оценка по локальному замеру) | ~+17 мин | ~+32 мин |

На машине 4 ядра, поэтому параллельно идут не больше 2 проверок.

Стоимость предложения решения — в первую очередь токены исследователя (Claude Code). Оценка — 100–300 тыс. токенов на кандидата: чтение журнала, правка кода, свой анализ на train.

## Решение

**Сопоставимые замеры для кривой** — фиксированная подвыборка `train_curve` из 50 семейств и 200 запросов, пропорционально кластерам ([curve_subset.py](../../case/dataset/curve_subset.py), sha256 `d4aecd33…`). Она обязательна для каждого предложенного решения. Baseline на ней даёт 0.488 при 0.508 на полном train. Разведочные замеры — через тот же train-сервис на полном train или других подвыборках, для уже зарегистрированных кандидатов; в кривую они не входят.

**Public** — у кандидатов, которых оркестратор считает перспективными, и обязательно у всех K финалистов. Ориентир — 15–20 проверок на кампанию.

**Лимит предложенных решений — 60.** Почему столько:
- **Пространство направлений.** Около 8 направлений:
  1. настройка BM25 (поля, токенизация, k1/b);
  2. четыре dense-модели;
  3. гибриды (взвешенная сумма, RRF);
  4. переранжирование двумя кросс-энкодерами;
  5. обучение на train (LTR, логистическая регрессия поверх признаков);
  6. линейный адаптер запроса;
  7. обработка запроса (нормализация, исправление опечаток);
  8. ансамбли.

  На каждое направление — 4–6 итераций с учётом неудач. Это 35–45 решений до ожидаемого плато.
- **Хвост.** Ещё ~15 решений на доводку лидеров, проверки устойчивости и разнообразие финалистов.
- **Время.** При среднем ~6 с на запрос (смесь BM25-, dense- и rerank-кандидатов): 60 × ~20 мин (кривая) + ~20 × ~38 мин (public) ≈ 33 ч машинного времени, при двух параллельных проверках ≈ 17 ч. Укладывается в одну неделю до ЧП2.
- **Токены.** 60 × 100–300 тыс. ≈ 6–18 млн токенов исследователей. Приемлемо.

**K = 5 финалистов, N = 2 итоговых.** Пять — чтобы в пакет вошли разные семейства решений (например, лучший dense-гибрид, лучший с переранжированием, лучший обученный), а не пять вариаций одного. Два итоговых — лучшее по качеству и лучшее по соотношению качества и времени. Правило равенства арены (при равном качестве — меньше времени) делает второе осмысленным.

**Правило выбора финалистов**:
- качество на `train_curve` и public;
- разрыв между train и public как признак переобучения;
- разнообразие подходов;
- ревью без замечаний: подготовка через build с квитанцией, нет заученных запросов, описания не менялись.

## Альтернативы
- **30 решений.** Хватает только на половину направлений, плато может не наступить. Слабее разбор B-6: меньше тупиков и скачков.
- **100+ решений.** ~40 ч машинного времени и до 30 млн токенов. Выигрыш сомнителен: пространство решений без дообучения энкодеров ограничено, и плато ожидается раньше.
- **Кривая по полному train.** ~1 ч на кандидата через контейнеры, 60 ч на кампанию — не укладывается.
- **Кривая по public.** Каждый кандидат подглядывал бы в public, что ускоряет переобучение на нём. Протокол арены не требует public на каждом шаге.

## Последствия
- `train_curve` фиксирован до поиска. Исследователь видит его состав: это train, и обучение на нём не запрещено. Поэтому разрыв между `train_curve` и public — главный индикатор переобучения в разборе B-6.5.
- Шум: стандартная ошибка на 200 запросах около 3.5 п.п., на 380 — около 2.5 п.п. Скачки кривой меньше ~5 п.п. не интерпретируются как значимые.
- Если реальное время контейнера окажется заметно больше оценки, лимит пересматривается **до** старта поиска новой версией этого ADR. Во время кампании лимит не меняется.
- Модель исследователей — Claude Sonnet 5.5 (`claude-sonnet-5-5`), effort high, индекс AA — в README (правило 0-1). Кампания идёт на лимитах подписки: паузы до сброса лимита растягивают её по календарю, но не меняют условия. Расход токенов на решение замеряется на подготовке.
