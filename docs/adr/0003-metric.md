# ADR-0003: Метрика подбора навыка — 0.7·acc@1 + 0.3·nP@3

- Статус: proposed (замораживается вместе с пакетом метрики до начала поиска)
- Дата: 2026-11-02

## Контекст
Карточка AR-04 задаёт метрики accuracy@1 и precision@3. Арена оптимизирует одно число: среднее score по примерам, направление `maximize`. У запроса один основной навык (`primary`) и иногда допустимые альтернативы (`acceptable`): 53 семейства из 378 имеют одну, 4 — две. Ответ решателя — ранжированный список id.

Ограничения:
- обычная precision@3 при одном релевантном навыке не превышает 1/3 и почти полностью дублирует hit@3;
- метрика не должна позволять «размазывать» ответ: длинные списки, повторы;
- ошибки оценщика нельзя превращать в 0 (правило арены).

## Решение
Для каждого примера считаем `rel = {primary} ∪ acceptable`:

- `acc@1 = 1`, если первый id ответа ∈ rel;
- `nP@3 = |top3 ∩ rel| / min(3, |rel|)` — precision@3, нормированная на достижимый максимум;
- `score = 0.7·acc@1 + 0.3·nP@3`; итог по набору — среднее (агрегатор арены по умолчанию).

Ответ — JSON-массив не более чем из 3 уникальных строк, каждая из каталога. Иначе ответ невалиден и получает 0 (`statistics.valid = 0`). Регистр и пробелы не нормализуются. Пустой массив валиден и получает 0. Повреждённый `reference` (не JSON, id не из каталога) — ошибка процесса, не 0.

`statistics` по каждому примеру (`valid`, `acc1`, `np3`) идут в журнал для отчёта. Срезы `hard`, по стилям, по росту каталога и MRR считаются отдельным отчётным скриптом и на score арены не влияют.

## Альтернативы
- **Только acc@1.** Проще, но теряет сигнал «правильный навык на 2–3 месте». Для навыка агенту это полезно: оркестратор может показать модели топ-3.
- **MRR или hit@3.** Отказались ради близости к карточке (acc@1 и precision@3). MRR даём в отчёте.
- **Ненормированная P@3.** Её максимум зависит от |rel|, и запросы с альтернативами получили бы непропорциональный вес.
- **Веса 0.5/0.5.** Главная задача — выбрать навык (top-1), поэтому acc@1 весит больше.

## Последствия
- Идеальный ответ — основной навык первым, все допустимые в топ-3. Ответ из одного основного навыка при наличии альтернативы получает 0.85, а не 1.0. Это осознанно: nP@3 вознаграждает полноту топ-3 (тест `test_primary_alone_misses_np3_when_alternatives_exist`).
- Добавление нерелевантных id в позиции 2–3 не штрафуется, но выдать больше 3 нельзя.
- Пакет метрики содержит `catalog_ids.txt`. Его совпадение с каталогом проверяет тест, при изменении каталога пакет нужно пересобрать и заморозить заново.
- «Жульнические» ответы покрыты тестами `case/metric/tests/test_score.py`: неверный формат, больше 3 id, повторы, чужие id, весь каталог, заучивание train.
