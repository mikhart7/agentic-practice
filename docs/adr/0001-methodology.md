# ADR-0001: Методология — арена DeepPavlov без изменений, роли в Claude Code

- Статус: accepted
- Дата: 2026-11-03

## Контекст
По ТЗ (B-0.2) навык выращивается на арене курса или на своей методологии, отличия от арены описываются в ADR. Нужно решить:
- чем ищем решение;
- кто исполняет роли;
- на чём крутятся кандидаты.

Решатель по теме (AR-04а) — ранжировщик без LLM. Модель нужна только ролям поиска.

## Решение
1. **Арена as is.** Используется [арена DeepPavlov](https://gitlab.deeppavlov.ai/deeppavlov/arena), закреплённая на коммите `a28eee3abd72d5af3445e718b0253ff7147b8d45`. Её код не копируется и не меняется: `scripts/setup_arena.sh` проверяет чистоту рабочей копии. Кейс оформлен по `cases/template` и подключён ссылкой `~/arena/cases/ar04a-skill-select → case/`. Подготовка и поиск работают в контейнере исследователя с клоном этого репозитория (`/srv/arena/train` → `/workspace`); то, что они пишут в каталог кампании `case/campaigns/c1`, оператор забирает в репозиторий через `git pull`.
2. **Роли по промптам арены.**
   - Подготовка — `prompts/prepare.md`: заморозка метрики, конфигурация train-сервиса с build, `preparation.md`, проверка готовности.
   - Поиск — `prompts/start.md`: оркестратор, исследователи-субагенты, ревьюер.
   - Подготовка и поиск — два отдельных запуска Claude Code, оба в контейнере `researcher` ([ADR-0006](0006-isolation.md)).
   - Оценщики — сервисы арены: `evaluator` для public и private, `evaluator.train` для train и build.
   Своих промптов, кроме условий кейса и кампании, нет.
3. **Харнес и модель исследователей.** Claude Code 2.1.280 (закреплён в `case/deploy/researcher.Dockerfile`), модель Claude Sonnet 5.5 (`claude-sonnet-5-5`), effort high. Внутри кампании модель и уровень effort не меняются (правило 0-1): при исчерпании лимита подписки ждём, а не переключаемся на другую модель. Индекс AA — в README, раздел «Модели».
4. **Решатель** — немодельный кандидат арены: `solve.py` в runner-образе без сети, локальные модели из закреплённого списка ([ADR-0004](0004-allowed-changes-and-models.md)).
5. **Изоляция** — штатная контейнерная схема арены ([ADR-0006](0006-isolation.md)).

## Альтернативы
- **Своя методология** (свой цикл «предложи → оцени»). Отклонено: арена уже даёт то, что пришлось бы писать и защищать заново, — журнал с родословной, кривую и AUC, лимит решений, однократную проверку private, изоляцию.
- **Форк арены с правками.** Отклонено: правки пришлось бы описывать в ADR и защищать, а нужды в них нет — кейс полностью описывается конфигурацией.
- **Копия арены в репозитории.** Отклонено: код арены без лицензии, и копия расходилась бы с источником. Достаточно ссылки и коммита.
- **Другой харнес** (opencode и т. п.) для ролей поиска. Отклонено для поиска: в Claude Code работают субагенты и worktree, на которые рассчитан `prompts/start.md`. Для проверки навыка (B-8) харнес будет открытым — это отдельное решение.

## Последствия
- Отличий от арены нет, поэтому в `docs/arena.md` не нужна таблица сравнения, только описание установки.
- Воспроизводимость: `bash scripts/setup_arena.sh` даёт ту же арену и тот же кейс.
- Трейсы агентов поиска выгружаются в `results/campaign-1/` и публикуются. Транскрипты оператора, видевшего private, не публикуются.
- Новая версия арены в середине кампании не подтягивается: коммит закреплён.
