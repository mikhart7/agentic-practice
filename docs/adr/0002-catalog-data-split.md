# ADR-0002: Каталог, данные и split

- Статус: accepted (split зафиксирован до поиска; хеши — в [generation_report.md](../../case/dataset/generation_report.md))
- Дата: 2026-11-03

## Контекст
Для AR-04а нужны:
- каталог из 50–200 навыков из открытых источников, с близкими навыками (hard negatives);
- запросы с разметкой «какой навык верный»;
- три раздела train, public и private из одного распределения, причём private фиксируется до начала поиска (B-4.2).

Открытого набора «запрос → навык» для каталога MCP-серверов нет.

## Решение
1. **Каталог — 189 серверов из официального реестра MCP**, версии закреплены ([catalog_selection.toml](../../case/dataset/catalog_selection.toml)).
   - Отбор ручной: 24 кластера близких навыков по 6–9 и 13 одиночных.
   - Решатель видит только `id`, `name`, `description`. Кластеры лежат отдельно в `catalog_meta.jsonl`, потому что в реальном каталоге их нет.
   - Сборка побайтово воспроизводима: `build_catalog.py build`.
2. **Запросы синтетические, генерирует LLM** по описанному промпту ([generation_prompt.md](../../case/dataset/generation_prompt.md)).
   - На навык 2 намерения (семейства), на семейство 4 перефразы разных стилей; `indirect` обязателен.
   - Эталон: `primary` и список `acceptable` — допустимые альтернативы для неоднозначных запросов.
3. **Split целыми семействами**, детерминированно (`generate.py split --seed 1`).
   - У каждого навыка одно семейство в train, другое — в public или private, с чередованием внутри кластера.
   - Получилось train 756 / public 380 / private 376 запросов, пересечение семейств пустое.
   - Public и private хранятся только у оператора; в git — только train.

## Альтернативы
- **Каталог из `anthropics/skills` и awesome-списков.** Отклонено: навыков мало, и они слабо пересекаются по функциям — не набрать кластеры близких навыков.
- **Единица каталога — отдельный tool, а не сервер.** Отклонено: у сервера одна понятная функция, а tools внутри сервера почти неразличимы без контекста. Это другая задача.
- **Запросы из MetaTool, ToolRet, ToolBench.** Отклонено: размечены под свои каталоги. Переразметка под наш каталог — та же ручная работа, только с чужим распределением.
- **Случайный split по запросам.** Отклонено: перефразы одного намерения попали бы в train и в private, и заучивание формулировок выглядело бы как обобщение.
- **Split по навыкам** (навыки private не встречаются в train). Отклонено: каталог фиксирован и известен решателю, а в реальной задаче ранжировщик видит весь каталог. Проверяем обобщение на новые формулировки и намерения, а не на новые навыки.
- **Больший held-out** (около 1 000 запросов в public и private). Отложено: потребовало бы больше намерений на навык. Ограничение по шуму описано в [case/dataset/README.md](../../case/dataset/README.md).

## Последствия
- Шум: стандартная ошибка acc@1 около 2.5 п.п. на split. Разницу меньше ~5 п.п. на одном split не считаем значимой. Это учитывается при выборе финалистов и в разборе.
- Один генератор для всех split: private ловит переобучение на train, но не на стиль генератора. Нужна внешняя проверка — 50–100 вручную написанных запросов вне поиска (задача оператора, до ЧП3).
- Ручная проверка `acceptable`: 44 семейства train (все 29 с альтернативами и 15 случайных) просмотрены 2026-11-06, исправлений нет ([results/data-review/accept-review.md](../../results/data-review/accept-review.md)). Проверка прошла после заморозки метрики, но разметка не менялась, поэтому заморозка не затронута.
- При изменении каталога пакет метрики (`catalog_ids.txt`) нужно пересобрать и заморозить заново ([ADR-0003](0003-metric.md)).
