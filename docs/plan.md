## Context

Практика курса Agentic LLM Systems (ИТМО × DeepPavlov), трек B, тема **AR-04а**. Даны фиксированный каталог навыков (описания не меняются) и запрос пользователя. **Ограничения среды:** WSL2, 4 CPU, 7 ГБ RAM, без GPU. Арена: `gitlab.deeppavlov.ai/deeppavlov/arena`, коммит `a28eee3`. ## Фаза 1. Домен и данные → ЧП1

**Каталог (фиксированный, ~150 навыков)** → `case/assets/catalog.jsonl`: `{"id","name","description"}`.
- Источники: `anthropics/skills`, awesome-списки Claude skills, реестр MCP (`registry.modelcontextprotocol.io`), `awesome-mcp-servers`. Указать лицензии и версии снапшотов.
- Единица каталога — навык или MCP-сервер целиком, а не отдельный tool.
- **Кластеры hard negatives специально:** 15–25 групп по 3–8 близких навыков (PDF и DOCX; несколько веб-поисков; Postgres, MySQL и SQLite; Slack и Teams и т. п.). Скрипт сборки — `case/dataset/build_catalog.py`, у каждого навыка записан cluster id.

**Запросы** → `case/dataset/generate.py`:
- **Семейство** = одно намерение пользователя и все его перефразы.
- На каждый навык 3–5 намерений, на каждое намерение 3–5 перефраз. Генерирует LLM (Claude): это подготовка данных, не решатель.
- Разнообразие по правилу о синтетике: 5–6 стилей (короткая команда, развёрнутая просьба, косвенная формулировка без ключевых слов, жаргон, опечатки), несколько промптов-шаблонов и шум.
- Каждая запись: `{"id","family","input":{"query"},"reference":{"primary","acceptable":[...]}, "tags":["hard"?]}`. Список `acceptable` проверяется вручную на выборке.
- Тег `hard` ставится, если основной навык из кластера близких.

**Split по семействам** (`GroupShuffleSplit` по `family`, стратификация по навыку, чтобы любой навык был в train). Ориентировочно:
- train ~600 запросов;
- public ~300;
- private ~300.

Обоснование: при p≈0.7 и n=300 стандартная ошибка accuracy ≈0.026, то есть различимы отрывы около 5 п.п. Замер стоит секунды, поэтому размер ограничивает только генерация. Public и private генерирует оператор, в git они не попадают.

**Внешняя проверка метрики** (не участвует в поиске): 50–100 реальных запросов, размеченных вручную или взятых из открытых бенчмарков выбора инструментов (кандидаты — MetaTool, ToolRet; проверить лицензии), привязанных к нашему каталогу.

**Обзор домена** → `docs/domain.md`:
- лексический поиск (BM25, расширение запроса);
- dense-ретривал (bi-encoder: e5, bge, MiniLM);
- гибриды (RRF, взвешенная сумма);
- кросс-энкодеры;
- learning-to-rank (LambdaMART);
- известные бенчмарки выбора тулов (ToolBench retrieval, MetaTool, ToolRet) и их цифры.

**Baseline** → `case/ways/baseline/solve.py`: BM25 (`rank_bm25`) по `name + description`, возвращает top-3 id.

## Фаза 2. Кейс арены → ЧП1

Оформляется по `cases/template` арены. Кейс лежит в `case/` проекта и подключается в `~/arena/cases/ar04a-skill-select` (симлинк или копия, скрипт описан в README).

- **`case/README.md`.** Вход — `{"query": str}`. Каталог берётся из `/assets/catalog.jsonl`. Ответ — JSON-массив до 3 уникальных id в порядке ранга.
  - **Разрешено:** код `solve.py` и его материалы. Это признаки, токенизация, гибрид, переранжирование, обученные на train веса в пакете кандидата, выбор и комбинация моделей из закреплённого списка.
  - **Запрещено:** менять описания и каталог (граница с AR-04б), сеть, LLM, модели вне списка, таблицы «запрос → ответ» по train.
- **Закреплённые модели** в runner-образе (ADR): например, `all-MiniLM-L6-v2`, `bge-small-en-v1.5`, `e5-base-v2`, `cross-encoder/ms-marco-MiniLM-L-6-v2`, `bge-reranker-base`. Итоговый список проверить на CPU по времени ответа.
- **Метрика** `case/metric/score.py` (`kind: command`, `maximize`, без модели):
  - невалидный ответ даёт 0: не JSON, не список, id не из каталога, дубликаты, больше 3 элементов;
  - `score = 0.7·acc@1 + 0.3·nP@3`, где `acc@1 = [top1 ∈ {primary} ∪ acceptable]`, а `nP@3 = |top3 ∩ rel| / min(3, |rel|)`;
  - веса и нормировку зафиксировать в ADR до поиска;
  - отдельный скрипт `case/metric/report.py` для отчёта: acc@1, P@3, MRR, срез `hard`, кривая при росте каталога 50→100→150. Он не влияет на score арены.
- **Тесты метрики** `case/metric/tests/test_score.py`:
  - верные и неверные ответы, частичное попадание в top-3, допустимый вместо основного;
  - неверный формат, чужие и повторяющиеся id, лишние элементы, пустой ответ;
  - «жульнический» решатель с захардкоженной таблицей train → проваливается на held-out семействах.
- **`case/dataset/README.md`:** источник, одно распределение, семейства, таблица размеров и обоснование.
- **`case/campaign/campaign.md`** (ADR), предварительно:
  - лимит **60 решений**: замер дешёвый, основная цена — токены исследователей Claude Code; плато ждём к 40–50;
  - K=5 финалистов, N=2;
  - 2–3 параллельных исследователя;
  - таймаут 60 с на пример.
- Подготовка по `prompts/prepare.md` арены: freeze и verify пакета метрики, `preparation.md` со свидетельствами, запуск оценщиков public и private (`search-readiness`).
- **ADR в `docs/adr/`:**
  - 0001 методология (арена как есть плюс Claude Code);
  - 0002 каталог, данные и split;
  - 0003 метрика;
  - 0004 граница разрешённых изменений и закреплённые модели;
  - 0005 лимит, K и N;
  - 0006 изоляция.
- `docs/arena.md`: роли, видимость, лимит, журнал, AUC, финализация, граница изоляции — своими словами (B-3).
